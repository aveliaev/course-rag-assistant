# ADR-001. Фиксированный пайплайн для B0

Статус — принято для КТ3.

## Контекст

Нужна воспроизводимая точка отсчёта для ответов по документам и подготовки двух форм. Для регистрации заявки необходимы доверенная кнопка, проверка владельца и атомарная запись в журнал. КТ2 задаёт B0 как обычный гибридный RAG и формы на правилах.

## Решение

Python задаёт последовательность шагов. Для ответа по документам выполняем один гибридный поиск и максимум один вызов GigaChat. Для формы используем версионированные локальные правила, состояние карточки и транзакционный шлюз. Оркестратор получает генератор и токенизатор через интерфейс ModelClient. Ответ модели проверяется Pydantic и сверкой меток источников.

## Альтернативы

| Вариант | Причина отказа для B0 | Условие пересмотра |
|---|---|---|
| Один промпт к модели | Качество ответа зависит от знаний модели о локальных правилах и редакциях | Применим как основной подход, если эталон ограничен задачами, где проверяемые ссылки на версии документов не требуются |
| Агент с планированием и повторным поиском | Добавляет вызовы и переменные в исходный эксперимент | Сравним декомпозицию B2 при систематической потере частей составного вопроса |
| Реранкер | Добавляет время и CPU на каждый ход | Сравним B3, если нужный документ регулярно есть в top-20 и выпадает из top-5 |

## Последствия

Бюджет и причины остановки проверяются на каждом маршруте. При смене редакций обновляется корпус и повторяется замер. Качество упрощений измеряем на тех же кейсах. Усложнение принимаем при измеримом выигрыше в пределах бюджета.
