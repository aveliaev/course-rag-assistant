# Проверка eval и независимая ИИ-разметка

**Исправленная версия:** [v2/README.md](v2/README.md), [300 кейсов](v2/fkn_golden_300.jsonl)
и [дизайн-документ 0.7](v2/design_doc_kt2.md). Ниже описан первоначальный аудит;
его входы, разметки и согласие сохранены для воспроизводимости.

Входные файлы скопированы без изменений из `origin/kt-2:KT-2/`.
Корпус `tmp_dataset` взят из `main`. Коммиты и SHA-256 записаны в
[`inputs/provenance.json`](inputs/provenance.json). Это объединённый локальный
пакет аудита двух веток, а не изменение исходных эталонов ветки `kt-2`.

Запуск из корня репозитория, Python ≥3.10:

```sh
python3 -m pip install -r eval/requirements.txt
python3 eval/audit.py
python3 -m unittest discover -s eval -p 'test_*.py' -v
python3 eval/agreement.py eval/annotation/annotator_a.jsonl eval/annotation/annotator_b.jsonl
```

В использованной среде Python 3.13.7 и PyMuPDF 1.27.2.3 уже установлены;
установка при этой проверке не выполнялась. Остальной код использует стандартную
библиотеку. Для JSONL, Markdown и DOCX сторонний парсер не требуется. Исходные
PDF и DOCX остаются в корпусе. TXT в `evidence/` — вспомогательное извлечение
текста; для DOCX номера — абзацы извлечения, а не номера пунктов документа.

## Результаты

- `reports/audit_summary.json`: агрегаты полноты и целостности.
- `reports/corpus_integrity.jsonl`: SHA-256 и наличие всех 1 828 файлов.
- `reports/linked_cases.jsonl`: для каждого из 300 кейсов — профиль, источники,
  конкретные пути, исходная версия, SHA-256 снимка, область, поля и их происхождение.
  Флаги программы, года или актуальности требуют проверки контекста вопроса;
  сами по себе не доказывают ошибку (например, при вопросе о переводе).
- `reports/version_observations.json`: проверенные расхождения названия редакции
  с изменениями в самом сохранённом тексте; 3 документа, 71 затронутый кейс.
- `annotation/tasks_dev.jsonl`: все 56 исходных dev-кейсов, одинаковый нейтральный
  пул документов и кандидатных фактов без авторского статуса/ролей источников.
- `annotation/RUBRIC.md`: зафиксированная до разметки инструкция.
- `annotation/annotator_a.jsonl`, `annotation/annotator_b.jsonl`: независимые
  первичные оценки; арбитраж не должен их перезаписывать.
- `reports/agreement.json`: согласие **до** арбитража, распределения, матрицы,
  расхождения, диагностика цитат и хеши использованных файлов.

`agreement.py` требует обе полные разметки, отклоняет пропущенные/повторные ID и
не подменяет их пересечением удобных кейсов. Для вырожденных распределений κ
равна `null`; для пустых наборов/полей оценка без знаменателя также `null`.
Отсутствующее поле не равно `null`; типы JSON сохраняются. Set-F1 — симметричное
согласие разметчиков, а не качество одного из них относительно истины.

## Ограничения

Сверка ID, хешей и полей профиля не доказывает правильность смысловых фактов.
Полная смысловая двойная проверка назначена на 56 dev, как предусмотрено §7.5;
244 test-кейса ею не покрываются. Ни один из этих подсчётов не является метрикой
работающего RAG-помощника. Нет исполнения действий/заявок, диалоговых продолжений,
интеграционных заглушек и подтверждённых записей изучения дисциплин.

Два разметчика — отдельные ИИ-агенты в раздельных контекстах с одной рубрикой.
Они не видят оценки друг друга, но используют общую модель, кандидатные факты
и источник документов. Это не человеческая разметка и не статистическая
независимость ошибок; требование исходного §7.5 о двух людях не выполнено.
Согласие не является доказательством истины; повторное согласие по ошибочному
факту возможно. Живой сайт и юридическая актуальность редакций не проверялись.

Во время первичного поиска формата в этом аудите были отображены первые 15
записей набора: 14 test (E001, E003–E015) и dev E002. Остальные test обрабатывались для
проверки зависимостей, метаданных и полей. Это надо учитывать в истории доступа:
название `test` не доказывает скрытый holdout. Для разработки конфигураций модели
в этом аудите test не использовался; сама RAG-система не запускалась.
