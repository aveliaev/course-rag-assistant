# Независимая проверка кандидата gold, версия 1

Единица — первый ответ на реплику dev-кейса. Задание содержит профиль,
сохранённые источники, неподтверждённые кандидатные факты и поля. Авторские
статусы и роли источников скрыты. Оба оценщика видят один и тот же пул кандидатов:
это независимая оценка общей рубрики, а не независимое изобретение фактов с нуля.
Разметчик не читает файл, заметки или ответы другого разметчика. Сеть не нужна:
проверяется снимок корпуса, а не актуальность правил на сегодняшний день.

Обязательна проверка самого текста, программы, года набора, периода и профиля.
Факт существования файла/ID не доказывает факт из gold. DOCX представлен
абзацами: номер строки TXT — номер извлечённого абзаца, а не пункт положения.
Для PDF сохранены маркеры страниц. Отрицательное утверждение «формулы нет»
проверяется чтением целого раздела/документа, а не ссылкой на отсутствующий пункт.
Проверка текстового представления не является визуальной сверкой PDF/OCR.

## Контракт, применяемый обоими разметчиками

Три сценария действий: `temp_pass`, `enrollment_certificate`, `sick_notice`.
Остальные запросы действий получают инструкцию по проверенному источнику или
предложение передачи при необходимости персонального решения; произвольные
новые формы не создаются. `student_id_duplicate` не равен `temp_pass`,
`medical_certificate` не равен автоматически `sick_notice`.

Статусы первого ответа: `answer`, `answer_partial`, `clarify`, `draft_ready`,
`refuse`, `escalation_offered`, `temporary_error`. Отсутствие правила в корпусе
допускает `escalation_offered` при причине `unsupported_in_scope`. Отправка и
создание тикета без отдельного согласия запрещены. Текстовое предварительное
согласие не заменяет подтверждение показанных актуальных полей.

`enrollment_certificate`: ID владельца, ФИО, программа, факультет, уровень,
курс — из профиля; язык — явно из реплики (язык интерфейса его не определяет);
цель — из реплики; число копий default 1, формат default `electronic` — правила
песочницы, не утверждение о реальной форме ВШЭ. Если неизвестно обязательное
поле, статус `clarify`, а не `draft_ready`.

`sick_notice`: период и наличие документа — из реплики, пропущенные контроли —
из реплики либо отдельного расписания с согласием. Скан и диагноз не нужны.
`temp_pass`: дата — реплика либо объявленный default «сегодня», корпус и причина
должны быть известны; профиль сам по себе корпус не задаёт.

В профилях нет списка изучаемых дисциплин. Для однозначного вопроса о текущей
ПУД конкретной программы можно сообщить правило опубликованной ПУД с явной
оговоркой об области. Нельзя утверждать, что студент зачислен на дисциплину.
При нескольких реализациях/годах или явном повторном изучении — уточнить либо
дать маркированные варианты. Текущий год сам по себе не доказывает год изучения.
Для вопроса, прямо задающего прошлый год, старый документ может быть применим.

## Файл разметки

Одна строка JSON на кейс; не пропускать трудные случаи. Поля:

```json
{
  "id": "E002",
  "annotator_id": "A",
  "annotator_kind": "ai",
  "status": "clarify",
  "scenario": "none",
  "answerability": "needs_context",
  "escalation": "not_needed",
  "gold_validity": "revise",
  "fact_labels": {"F1": "supported", "F2": "uncertain"},
  "required_fact_ids": ["F1"],
  "source_ids": ["syl_1163609002"],
  "field_values": {},
  "evidence": [{"fact_id": "F1", "document_id": "syl_1163609002", "line_start": 1, "line_end": 3, "quote": "дословный фрагмент", "comment": "почему он подтверждает или опровергает факт"}],
  "notes": "краткое основание выбора статуса и исправлений"
}
```

Пример показывает схему, а не правильную разметку E002.

- `scenario`: `none` / `temp_pass` / `enrollment_certificate` / `sick_notice`.
- `answerability`: `full` / `partial` / `none` / `needs_context`.
- `escalation`: `not_needed` / `offer` / `uncertain`.
- `gold_validity`: `valid` / `revise` / `uncertain`. Оценивает кандидатные факты
  и поля; несоответствие статуса старого gold уточнит отдельный анализ.
- `fact_labels`: для каждого кандидатного F-ID ровно одно из `supported`,
  `unsupported`, `uncertain`. `supported` означает, что факт верен в применимой
  области и с нужными оговорками; это ещё не обязательность его в первом ответе.
  Для контрактного требования источник — `contract`, точная ссылка `RUBRIC.md`.
  Истинность по общим знаниям без источника недостаточна.
- `required_fact_ids`: факты, обязательные именно при выбранном первом ответе;
  при уточнении формулы не обязательны. Недостающие новые факты описать в notes.
- `source_ids`: только документы, действительно поддерживающие ответ/границу,
  без кандидатов, неприменимых к студенту. Для отказа по контракту допустимо [].
- `field_values`: значения полей только для поддерживаемого сценария MVP;
  неизвестное — null. У не-MVP сценария {}. JSON типы сохраняются.
- `evidence`: дословные выдержки с локаторами для проверенных фактов. Общая
  выдержка может поддерживать несколько фактов, но связь должна быть объяснена.

При сомнении использовать `uncertain` и указать, чего не хватает. Не подгонять
оценки под порог согласия. Не менять исходные файлы и не обсуждать оценки до
фиксации обеих разметок. Арбитраж хранится отдельно от первичных меток.
